## Things learned this session

- **Line endings:** Windows uses CRLF, Linux uses LF. `.gitattributes` with `* text=auto eol=lf` stores LF in the repo. `git add --renormalize .` fixes files already in the repo (index); the working folder needed a re-checkout to match.
- **Version ranges:** `^5.9.0` allows any 5.x ≥ 5.9.0; `~6.0` allows only 6.0.x. The lock file pins the exact resolved version for every machine.
- **"latest" isn't always compatible:** check peer dependencies before upgrading (the TypeScript 7 case).
- **Git hooks:** scripts Git runs at set moments; for "pre-" hooks a non-zero exit code aborts the operation. `.git/hooks` isn't committed, so Husky sets `core.hooksPath = .husky/_` via the npm `prepare` script. Generated stubs in `.husky/_/` call `h`, which runs your own `.husky/<hook>` file with `node_modules/.bin` on `PATH`.
- **Commit timeline:** pre-commit → prepare-commit-msg → commit-msg → commit created → post-commit.
- **lint-staged:** backs up state, runs tools on staged files only, re-stages fixes, restores the backup on failure.
- **commitlint:** `--edit "$1"` reads `.git/COMMIT_EDITMSG`; `npx --no` refuses to download. The message `added stuff` was rejected (`type-empty`, `subject-empty`).
- **Hooks can be bypassed** (`--no-verify`, `HUSKY=0`, web edits, no `npm install`), so CI + branch protection is the real gate.
